# VK WorkSpace Ad Blocker

Убирает верхний баннер и боковой рекламный фрейм на `app.workspace.vk.ru` или `e.mail.ru`.

«Они» запрещают нам пользоваться Зарубежными почтовыми службами.
«Другие» запрещают пользоваться бесплатно почтовыми сервисами в РФ, отключая доступ по SMTP/IMAP и POP, чтобы больше заработать денег.
«Эти же» навязывают просмотр рекламы в Web и Своих приложениях.
…. но как бы <b>«с какого поркуа?»</b>


## Почему не AdGuard

AdGuard и подобные блокировщики полагаются на статические CSS-селекторы и
списки доменов. В SPA-приложениях класс-имена и структура рекламных блоков
пересобираются при каждом релизе фронтенда, поэтому фильтр быстро протухает
и реклама возвращается.

Это расширение вместо хрупких селекторов использует:

1. **Текстовую метку "Реклама"** — по закону "О рекламе" (ФЗ-38) рекламный
   блок обязан нести эту пометку, убрать её нельзя. Скрипт постоянно (через
   `MutationObserver` + подстраховку таймером раз в секунду) ищет такой
   текст в DOM, поднимается к ближайшему контейнеру-карточке подходящего
   размера и скрывает его целиком (`display:none` + `visibility:hidden`) —
   независимо от того, как называются классы вокруг.
2. **Список известных рекламных хостов** (`mradx.net`, `ad.mail.ru`,
   `filin.mail.ru` + домены, добавленные вручную через попап) — по нему
   скрипт прячет `img`/`iframe`, CSS `background-image` и lazy-атрибуты
   (`data-src` и т.п.), которые ссылаются на эти хосты, независимо от того,
   есть ли рядом текстовая метка.
3. **Авторскую метку самого сайта** — почта сама помечает свои рекламные
   строки в списке писем CSS-классом с суффиксом `-adv` (например
   `letter-list-item-adv`); скрипт использует это как дополнительный,
   более надёжный якорь на e.mail.ru.

Расширение не блокирует сетевые запросы (без `declarativeNetRequest`) —
оно только прячет уже отрисованные DOM-элементы, чтобы не было риска
сломать загрузку самого приложения. Ради этого же скан идёт через
`requestIdleCallback` и обрабатывает мутации DOM пачками, а не синхронно
на каждое изменение.

## Установка (Chrome / Edge)

1. Открой `chrome://extensions` (в Edge — `edge://extensions`).
2. Включи "Режим разработчика" (переключатель справа вверху).
3. "Загрузить распакованное расширение" → выбери папку `extension` (эту).
4. Открой/обнови вкладку `https://app.workspace.vk.ru/` или `https://e.mail.ru/inbox/`.

## Если что-то всё же проскочило

1. Открой DevTools на странице (F12) → вкладка Network, найди запрос,
   который грузит баннер, скопируй домен (например `xxx.ru`).
2. Нажми на иконку расширения → вставь домен в текстовое поле → "Сохранить".
   Домен уйдёт в `chrome.storage.sync`, content-script подхватит его через
   `storage.onChanged` и сразу пересканирует страницу — без перезагрузки
   расширения.
3. Либо просто напиши мне домен/скриншот — добавлю его в стартовый список
   `BASE_HOSTS` в `content.js`.

Проверить, что скрипт вообще работает и сколько блоков он уже скрыл, можно
в консоли страницы:

```js
window.__vkAdsBlocker.stats()
```

## Структура

- `extension/manifest.json` — MV3-манифест. Content-script подключается на
  `app.workspace.vk.ru`, `*.cdn-vk.ru`, `e.mail.ru`, `*.imgsmail.ru`,
  во все фреймы (`all_frames: true`), с `run_at: document_start`.
- `extension/content.js` — вся логика: поиск метки "Реклама" в тексте,
  проверка доменов img/iframe/CSS-фонов/lazy-атрибутов по списку известных
  рекламных хостов, распознавание авторского класса `-adv`, защитные
  эвристики от случайного скрытия чужого контента (запрет на
  `<body>/<html>`, лимиты размера контейнера, "safe zone" по классам
  строк письма) и постоянное сканирование через `MutationObserver` +
  периодический `scan()`. Работает постоянно, а не один раз при загрузке.
  Хранит короткий буфер логов в `chrome.storage.local` и отдаёт статистику/
  логи через `window.__vkAdsBlocker` (`stats()`, `dumpLog()`, `printLog()`).
- `extension/options.html` / `extension/options.js` — попап расширения:
  статистика блокировок на текущей вкладке + текстовое поле для добавления
  доменов (хранятся в `chrome.storage.sync` как `extraDomains`).
